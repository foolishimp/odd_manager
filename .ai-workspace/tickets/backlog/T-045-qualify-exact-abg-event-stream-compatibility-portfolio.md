# T-045: Exact Event-Stream Compatibility Qualification

## Outcome

A durable, replayable qualification binds the exact installed `odd_manager`
server/browser path to the six terminal Hello World subjects, at least one
non-terminal Data Mapper subject, and the complete negative carrier matrix.
Any ABIogenesis 5.0 label is emitted only for a carrier that itself publishes
the exact accepted 5.0 identity and passes the same portfolio.

## Scope

- Pin each external source checkout, run root, identity carrier, event carrier,
  optional proof, and observed digest in a durable qualification manifest.
- Exercise discovery, incremental append, carrier mutation, late terminal and
  proof reconciliation, retries/continuations, payload rejection, large line,
  large carrier, unknown kind, malformed event, path escape, identity conflict,
  digest mismatch, stale Project/run result, pagination, and accessibility.
- Run through the installed development server and browser causal path.
- Publish separate dispositions for exact 4.6 carrier support, ABIogenesis 5.0
  development readiness, and exact ABIogenesis 5.0 compatibility.

## Acceptance

- All six completed Hello World carrier count/digest/terminal relations agree
  with their proofs through the installed Product path.
- A non-terminal Data Mapper run is visible without proof and without a
  manufactured process status.
- Rust Service retains retry history with correct aggregate convergence.
- Browser payloads and state remain bounded for the largest selected stream.
- Negative subjects fail closed with exact source-linked diagnostics.
- Proof artifacts are tracked, portable or reproducibly resolved, and bind the
  exact candidate commit and dirty-state posture.
- A 5.0 claim is absent until an exact self-identified 5.0 carrier passes; if
  no such carrier is available, the ticket remains partially blocked rather
  than relabeling the 4.6 subjects.

## Non-Closure

- Unit fixtures, analyzer output, or direct service calls without the installed
  browser path.
- A transient `/private/tmp` receipt or untracked external run reference.
- Event count alone without exact bytes, identity, and digest reconciliation.
- Claiming a broad semver range from one exact carrier.
- Treating Product-owner wave naming as carrier release identity.

## Current Checkpoint

The durable qualification manifest pins the exact ABIogenesis
`5.0.0-dev.286` artifact, six latest terminal odd_glc Hello World carriers,
the latest stopped 69 MB Data Mapper carrier, and the significant stopped
126 MB Data Mapper carrier. Direct service qualification proves exact 5.0 root
envelope readiness, exact 4.6 flat-carrier support, proof reconciliation,
retry non-inflation, non-terminal posture, and bounded browser payloads. The
source-blind installed candidate also passes the exact 5.0 emitter fixture and
latest stopped Data Mapper through browser paging and lazy detail.

This is not T-045 closure. Installed causal-path coverage of all six terminal
portfolio subjects, the full T-043/T-044 semantic surfaces, an accepted durable
qualification release, and a self-identified odd_glc-on-5.0 runtime carrier
remain absent or unclosed. The qualification manifest therefore records three
separate dispositions instead of promoting a partial result into Product
compatibility.
